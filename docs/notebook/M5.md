## 2026-10-25T15:37-0700 — decision: the skill's documents ship in the package as symbolic links
`--skill` must read through `importlib.resources`, but SKILL.md has to sit at the skill
folder's root, outside the package. Options: a copy kept equal by a test (drift and double
edits), a second setuptools package mapped onto the skill folder (not importable when run
from the script path, so two code paths), or symbolic links inside the package. Chose the
links: `order_history/agent_skill.md -> ../../SKILL.md` and
`order_history/vendors/<id>.md -> ../../../vendors/<id>.md`. One code path in every mode;
setuptools stores the targets' contents in the wheel (checked in the scratch install). The
link is not named `SKILL.md`, since some agents scan skill folders recursively and a
case-insensitive disk would match `skill.md` too. Windows checkouts without symlink support
would break `--skill` from a clone; Windows is not a goal (design A1).

## 2026-10-25T15:37-0700 — decision: version line, `skill <store>`, plugin version
- `--skill` inserts one line after the frontmatter: "Printed by `order-history --skill`,
  version X." The frontmatter stays first, so the output is a complete SKILL.md.
- `skill [STORE]` also prints `vendors/<id>.md`, so an agent with only the installed
  command (SKILL.md written by `--skill > ...`) can still read a store's notes.
- Output is written as UTF-8 bytes whatever the locale (the docs hold non-ASCII
  characters); a test runs the entry script with `LC_ALL=C` and `PYTHONIOENCODING=ascii`.
- `plugin.json` sets `version` equal to `__version__` (a test checks). Without it the
  validator warns, and Claude Code would version by commit; pinning ties a plugin update to
  a release, which is also when a page shell for that version exists.

## 2026-10-25T15:37-0700 — decision: add a marketplace.json beside plugin.json
Claude Code installs plugins only from a marketplace (or per session with `--plugin-dir`).
The design left "repo URL or marketplace listing" open. A one-entry
`.claude-plugin/marketplace.json` with `"source": "./"` makes the repository its own
marketplace, which is the "install from the repo URL" option
(`/plugin install order-history --marketplace curtisgalloway/order-history`); a listing in
someone else's catalog stays open. Both manifests pass `claude plugin validate --strict`
(Claude Code 2.1.310); the only note is a missing listing icon, which only matters for
Anthropic's directory. Not loaded into a real session: that would need launching Claude
Code with the plugin, which this milestone doesn't do.

## 2026-10-25T15:37-0700 — surprise: pyproject.toml changed what pyink formats
After adding `pyproject.toml`, `pyink --check` wanted to reformat two files this milestone
hadn't touched (`store.py`, `tests/test_import.py`) into parenthesized `with` blocks. pyink
reads `requires-python = ">=3.10"` and now targets 3.10+, where that syntax is allowed.
Applied it (formatting only; both suites pass on 3.10 and 3.15) rather than pinning an older
target.
