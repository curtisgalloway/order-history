# M4 — Update

Goal: [plan M4](../implementation-plan.md#m4--update): `order-history update` fills the
Adafruit item cache (on by default, with the old fetcher's politeness rules) and, only with
`--amazon-images`, the Amazon image cache, then rebuilds the page; exit codes 20/21 for
throttling, 3 for a missing lookup email.
Verdict record: [M4 evidence](../evidence/M4.md)

## 2026-10-25T15:01-0700 — opening
Starting revision: `e9fc3a3` (`origin/main`, M3 merged as PR #5) on branch `m4-update`, in
the reused worktree. Pre-existing changes: only the untracked, gitignored `.no-pitch`.
Approach: port `15fb0ad:search/fetch_adafruit_items.py` and `fetch_images.py` into
`enrich(vendor_dir, opts)` in the two vendor modules, with the network call, the sleep and
the jitter source injected through an options object, so tests stub all three and no test
or manual run reaches either store. `update` runs each vendor's `enrich`, then rebuilds
under the import lock when a cache changed. User decision recorded in this milestone: M3
review F1 resolved by turning on immutable releases (2026-10-25).

## 2026-10-25T15:11-0700 — decision: shape of enrich() and update
- A new `order_history/fetching.py` holds what both vendors share: `Options` (the email,
  `--amazon-images`, `--dry-run`, and the injected `urlopen`, `sleep`, `uniform`,
  `random`, `log`, `today`), `new_result()` and an atomic 0600 JSON writer. The tests'
  base class replaces the default `urlopen` with one that fails the test, so a forgotten
  stub can't reach a store.
- Amazon's `enrich` returns "skipped" before reading anything without `--amazon-images`,
  so not even the images-na CDN probe (an Amazon host) runs.
- `update` takes its own `.update.lock` while fetching (two updates must not both rewrite a
  cache) and the import lock only for the rebuild, so a long image run doesn't block
  imports. A held import lock at rebuild time exits 21 (caches saved, page stale).
- Email is needed only when there are orders to fetch, so a scheduled run with nothing
  missing needs no email (the old script asked first).
- The old `--delay`, `--limit` and `--refresh` flags are not carried over: none is in the
  plan, and `--delay` could lower the 10 s floor.
- Added `--dry-run` (house rule: every mutating command has one); it sends nothing.

## 2026-10-25T15:11-0700 — decision: exit codes for update
M2 gave 20 "nothing changed, retry is free" and 21 "partly done, reconcile". `update`
keeps those meanings, which are the house bands: 20 when nothing was saved (throttled,
robots.txt disallows or is unreadable, every lookup failed, another update running), 21
when some lookups were saved and then the run stopped or other lookups failed, or the
rebuild couldn't take the import lock. Considered 12 ("denied by policy") for a
robots.txt refusal: the plan's criterion says 20, a refusal can lift later, and a retry
costs one robots.txt request, so 20 stays. Lookups that fail without throttling (a 404,
a page that isn't the order's) are skipped as before and counted in `failed`; the old
script exited 1 for them, which this CLI reserves for "found nothing".

## 2026-10-25T15:11-0700 — decision: politeness carried over, with three deliberate widenings
Unchanged: the User-Agent string (so robots.txt rules keep matching), robots.txt read with
it, `max(10, Crawl-delay)` plus `uniform(0, delay/2)` between lookups and none before the
first, cached orders never refetched, stop at 429/5xx; Amazon's 8-way CDN probe, 2 s x
(0.75–1.25) after each product page, stop at a captcha/429/503, save every 250/25.
Widened: robots.txt errors are caught as `OSError` (a raw timeout used to crash the old
script; it now stops the run), and a lookup's timeout is skipped like a URLError; an
`http.client` error is turned into `OSError` (the M3 F3 lesson). ASINs sort by order date
rather than the raw timestamp (ties within a day can reorder).
