# M7 — Saved orders: `add`, merging, pruning

Goal: [plan M7](../implementation-plan.md#m7--saved-orders-add-merging-pruning):
`order-history add` saves orders read from Amazon's order pages to
`<data>/amazon/order-pages.json`; `amazon.load()` merges them; import prunes them;
`status` reports `saved_orders` and `checked`.

## 2026-10-25T22:20-0700 — decision: where the code lives, and what `checked` reads
- A core module `saved.py` owns the file format, input validation, `add` and pruning;
  the Amazon module only declares `SAVED_ORDERS`, checks its ID and ASIN shapes and fills
  its links and site in `saved_order()`, and calls `saved.merge()` from `load()`. The
  design's "storage is Amazon's" holds in that the file sits in `<data>/amazon/` and is
  merged by the Amazon module; the format is shared so a later store opts in with the
  same two names.
- `saved.py` takes no locks; the CLI holds the import lock (or the shared one for a dry
  run) around `saved.add`, as `build` does. That also avoids a `store` ↔ `saved` import
  cycle (`store` imports `saved` for pruning).
- `checked` is the later of the file's own `checked` and `current/`'s mtime. Checked on
  this Mac: renaming a folder keeps its mtime (ctime changes), and import writes the export
  into a fresh staging folder, so `current/`'s mtime is the install time. No marker file,
  so existing data folders (M6's) work with no migration.

## 2026-10-25T22:20-0700 — decision: input rules the design left open
- Unknown fields are refused (a typo like `quantity` would otherwise vanish), and so are
  `store`/`source`/`url` (the tool fills them) and `summary` (design). An order needs at
  least one item: an itemless Amazon order would draw as "(item list not in export)",
  unlike any exported one (G2).
- Order IDs must look like `111-1234567-1234567` and ASINs like ten letters or digits,
  since both go into links on the page and into `update`'s image URLs.
- `site` defaults to `Amazon.com`, as exported physical orders have; the page hides that
  value, so it changes nothing visible, but `search amazon.com` matches as for the export.
- `status` goes through `model.status`, so `Authorized` would read `In progress` as in
  the export. Amounts may be strings or numbers; qty a whole number of at least 1;
  NaN and infinity are refused. Item totals use `Decimal`, not floats.
- `status` gains `stale` (more than 30 days since `checked`) beside `checked`, so M8's
  skill rule reads one boolean instead of doing date arithmetic; the boundary is tested
  (exactly 30 days is not stale, one second more is).

## 2026-10-25T22:20-0700 — decision: pruning failures never fail an import
Pruning runs after a successful swap. If it fails (an unreadable `order-pages.json`, a
write error), the import stands and the report's `saved_orders` carries `error`: nothing
is lost, because `load()` already hides saved IDs the export has, and the next import
prunes again. A corrupt `order-pages.json` makes `add`, `search`, `status` and the page
build exit 2 with the path, rather than silently dropping saved orders, and nothing
overwrites a file the tool couldn't read.
