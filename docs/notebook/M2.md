Starting revision: `630d459` (`origin/main`, M1 merged as PR #3) on branch `m2-import`,

Approach: give each vendor `read(folder)` (export only, no caches), `install` and an

## 2026-10-25T14:22-0700 — decision: vendors gain read(folder); compare uses exports only
`load()` merges the caches (`images.json`, `items.json`), which would make an Adafruit
comparison show fetched items on both sides. Each vendor now has `read(folder)`, which
reads an export folder alone; `load()` is `read(current)` plus the caches. Adafruit's
export has no item lines, so its item counts in a report are always 0 until M4.

## 2026-10-25T14:22-0700 — decision: exit codes the design's table leaves open
Following the house CLI bands: another import holding the lock, and a swap or rebuild
failure that was rolled back, exit 20 (nothing changed, retry is free). A rollback that
itself fails exits 21 (reconcile first) and names where the previous export is. A folder
holding a symlink or special file exits 30, like an unsafe zip member. A folder that
contains the data folder exits 2.

## 2026-10-25T14:22-0700 — decision: small import choices
- Item rows are matched by (order ID, ASIN, or name when there is no ASIN), counting
  repeats, so a renamed title shows as a finding rather than as removed + added.
- Amazon findings cover every item matched by ASIN, not only digital ones. A title going
  from `(no product name)` back to a name counts as renamed.
- `--dry-run` stages in a system temporary folder, takes no lock and leaves leftover
  staging alone, so the data folder stays byte-for-byte unchanged (even `amazon/` is
  not created).
- Imports hold an `fcntl.flock` on `<data>/.import.lock`; the file is never removed.
- Zips also refuse duplicate member names, and files are created with `open(..., "xb")`
  so nothing is overwritten.
- Adafruit imports from its CSV only; a folder holding `order_history.csv` is not
  claimed (exit 2). Amazon imports from a zip or a folder.
- An export with the same `as_of` as the current one imports without `--force`.

## 2026-10-25T14:22-0700 — attempt: rollback left an empty archive/ folder
The first rollback tests failed because the swap's `makedirs(archive/)` survived the
undo. The rollback now removes `archive/` with `os.rmdir` when this import created it
and it is empty; `rmdir` can't remove anything with contents.

## 2026-10-25T14:22-0700 — surprise: a folder import copies the whole folder
R10 says the in-checkout Amazon export migrates "as a directory", but that export sits at
the checkout root beside the code, `.git` and `archive/`. Importing the root would copy
all of it. M2 copies whatever folder it is given (minus nothing); M6 has to gather the
export folders into their own directory first, or import the original zip. Added to the
backlog.
