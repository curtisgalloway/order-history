# M3 — Node-free page and retiring `search/`

Goal: [plan M3](../implementation-plan.md#m3--node-free-page-and-retiring-search): the
page reads its data from a `<script id="order-data">` element, `page.py` fills a shell
from the cache, a local build or the release download, `import` rebuilds, `search/` is
deleted, and CI gains a `page` job plus a release workflow.
Verdict record: [M3 evidence](../evidence/M3.md)

## 2026-10-25T14:35-0700 — opening
Starting revision: `15fb0ad` (`origin/main`, M2 merged as PR #4) on branch `m3-page`, in
the reused worktree. Pre-existing changes: only the untracked, gitignored `.no-pitch`.
Branch protection on `main` requires `build` and `lint` (read with `gh api`).
Approach: `git mv search/app web`; the app takes its data as a prop from `main.tsx`,
which parses the script element and checks a `format` number; `page.py` builds the page
data from the vendors, escapes `<` and writes `index.html` atomically; the shell lookup
takes injectable fetch and build functions so tests never run npm or touch the network;
`import`'s `rebuild=` hook calls it. Then CI and `release.yml`, then delete `search/`.

## 2026-10-25T14:46-0700 — decision: how the page gets its data and handles a mismatch
`App` takes the data as a prop; `main.tsx` reads `#order-data` through `loadData()`
(`web/src/load.ts`), which returns a message for an empty element (the bare shell),
damaged JSON, or a `format` other than `DATA_FORMAT`. `page.py` escapes every `<` as
`\u003c`, not only `</`: that also covers `<!--` and `<script`, which can change how a
browser parses script text. A test keeps `page.FORMAT` and `DATA_FORMAT` equal.

## 2026-10-25T14:46-0700 — decision: small page choices the plan left open
- The local build is never cached, so edits to `web/` show up; only downloads are cached.
  A failed local build falls through to the download, and exit 4 names every reason.
- The cache honors `XDG_CACHE_HOME`, like the config honors `XDG_CONFIG_HOME`.
- `index.html` is written 0600. `data.json` (in the design's data-folder sketch) is not
  written: nothing reads it, and a second file of purchase data would make the write
  non-atomic. Agents use `--json`.
- A page-shell failure during `import` rolls the import back (design, import flow step 7
  onward) and keeps exit 4: `_swap` now keeps a rebuild hook's own `StoreError` code.
- Added `order-history build` (rebuild by hand). The page's messages and M6's "clear the
  cache and rebuild" step need a way to rebuild without re-importing.
- The release has two jobs: `shell` (read-only token; runs npm) and `publish`
  (`contents: write`; runs only `gh`). It refuses a tag that isn't `v` + `__version__`.
- `search/` is ignored as a whole now (its leftover `index.html` and `images.json` hold
  purchase data in an old checkout).

## 2026-10-25T14:46-0700 — surprise: the fake npm in a test had no PATH for mkdir
The stub `npm` shell script ran with PATH set to its own folder only, so `mkdir` and `cp`
were not found (exit 127). Fixed with `/bin/mkdir` and `/bin/cp`.

## 2026-10-25T14:46-0700 — surprise: browser extension refuses file:// URLs
Claude in Chrome answered "Can't interact with browser-internal or unparseable URLs" for
the `file://` page (twice, also after a real page was open). The pages were served from
the scratch folder by `python3 -m http.server` on 127.0.0.1 instead and checked there:
the fixture page searched correctly, the page built from a cached shell with no node on
PATH rendered, the format-2 page showed the mismatch message, and a `</script>` title
stayed text. Opening from `file://` itself is not checked by the browser in this session.
