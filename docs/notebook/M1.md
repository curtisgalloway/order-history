## 2026-10-25T14:04-0700 — decision: search returns orders holding only matching items
`search.ts` has two rules: the Items view (every term in order fields + one item) and the
Orders view (each term in the order or in any item). R5 says "the order's fields count
toward each item", which is the Items view, so `search.py` uses that rule and groups the
hits by order, newest first. `feather jumper` (terms on two items) matches nothing; the
case file records that on purpose.

## 2026-10-25T14:04-0700 — decision: small CLI choices the design left open
- The config file honors `$XDG_CONFIG_HOME` (the plan's tests redirect it), falling back
  to `~/.config`.
- `init` on an existing folder keeps its mode and says "using existing"; it never chmods
  a folder it did not create. A config file that isn't valid JSON is reported (exit 2),
  not overwritten.
- `status` gaps: Amazon counts ASINs with no `images.json` entry; Adafruit counts
  orders with no `items.json` entry.
- `order ID` found in two stores exits 2 and asks for `--store`.

## 2026-10-25T14:04-0700 — surprise: build.py needs Python 3.12
`money()` in `search/build.py` nests double quotes in an f-string, which is a syntax
error before 3.12. `model.money()` is rewritten for 3.10. The test comparing the new
loaders with `build.py` skips below 3.12, so CI's 3.10 leg skips it and the latest leg
runs it.

## 2026-10-25T14:04-0700 — attempt: lint
pylint 4.1.3 with Google's rc flags single quotes inside f-strings
(`inconsistent-quotes`), then `.format()` (`consider-using-f-string`). On 3.10 an
f-string can't reuse its own quote, so values are pulled into locals or concatenated.
Clean afterwards; pyink reformatted four files.
