## Milestone definition

As planned (moved here from the implementation plan at completion):

**Outcome:** `vendors/amazon.md` gains "Catching up from order pages": status first; the
order list read newest first until a known ID (checked with `order-history order <id>`),
at most 3 pages before asking; each new order's details page read by its
`data-component` hooks (quantity from the image badge, absent means 1; shipment status
to `In progress` or empty; grand total as the order total); then `add --dry-run`,
report, `add`. Stop at any sign-in prompt; never type a credential. SKILL.md gains the
rule: only when asked, and when answering from Amazon data whose `checked` is over 30
days old, suggest a refresh once per conversation. `design.md`'s "no email source"
non-goal and phase 2 outline point to the new design.

**Design coverage:** G1 (flow), G4 (rule). **Dependencies:** M7.

**Scope:** documentation and one manual run. Excluded: digital orders, older-order
status changes, other stores, unattended runs.

**Acceptance criteria:**

- One real catch-up with the user present finds the orders newer than the export,
  `add --dry-run` reports them, and after `add` a search finds a new order.
- No order ID, product name, date or count from the real run appears in a tracked file
  (the evidence describes the run in generic terms).
- `tests/test_skill.py` passes (the skill and vendor docs are still emitted).

**Verification:** the project checks; the manual run recorded in `docs/evidence/M8.md`.

**Review:** `review-swarm --close` (it will likely pick the light tier for a docs
change). Focus: the steps match what the pages showed, and no credential or captcha
step is left to the agent.

**Sizing and checkpoint:** small; the manual run depends on the user being available.
If they aren't, land the docs and leave the run as the open item.

## What was built

- **`vendors/amazon.md`, "Catching up from order pages"** (a new section after "Getting
  the export"): only when asked; stop at any sign-in, verification or captcha and never
  type a credential; a note that some browser tools refuse text holding a URL with a query
  string. Steps: `status` first (email confirmation dates as a signal only); order IDs
  from the order list, newest first, each checked with `order <id> --store amazon --json`
  until a known one (the rest of that page read too), at most 3 pages before asking, and
  a warning about the list's default 3-month filter; each new order read from its details
  page by `data-component` hooks (grand total once, unit price once from the doubled
  text, quantity from the image badge, absent means 1; amounts without `$`; no item total
  and no `summary`; seller not stored); status `In progress` while any shipment is
  undelivered, omitted when all are delivered, `Cancelled` kept; the document written to a
  `mktemp -d` folder; `add --dry-run --json`, report, `add` when the user agrees, delete
  the folder, `search` to check; an empty `orders` list recorded with `add`. Page text is treated as data, and an order ID or ASIN is used in a
  command or URL only in its expected shape (review F1).
- **SKILL.md:** "Is the data current?" reads `status`'s `stale`, suggests a catch-up once
  per conversation and runs it only on a yes; also suggests it (within the same once)
  when a recent order isn't found while `stale` is false (user decision 2026-10-25, "Yes,
  suggest it"). Pointers to the flow from "First run" and "Saved orders: add"; catch-up
  wording in the frontmatter description.
- **design.md:** the email non-goal and key decision now say dates only, as a signal; a
  revision note; the phase 2 outline notes that `--provisional` is dropped and the download
  flow is built.
- **Privacy fix:** example amounts and the example item name in earlier docs and test
  fixtures came from a real order; replaced with invented values (SKILL.md's and
  design-order-pages.md's `add` example, `tests/test_add.py`'s fixtures), and an example
  delivery date in design-order-pages.md likewise.

## Limitations and blockers

- Unobserved in the real run: no quantity badge at quantity 1, an order with several
  shipments, and status wordings other than "Arriving …" (for example "Shipped" or
  "Delivered"). The steps state the expected behavior; the first run to meet one should
  confirm it.
- The page shows a local order date and the export a UTC one, so a late-evening order can
  differ by a day until the export replaces it.
- The `data-component` hooks can change without notice; only the skill's steps need to
  follow.
