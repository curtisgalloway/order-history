## Migration

Run by SKILL.md's "Migrating from an in-checkout layout", with the CLI from this branch
(`python3 skills/order-history/scripts/order-history`; not installed on `PATH`).

1. **Counts before migrating.** From the last in-checkout build's
   `search/app/src/generated/data.json` (built at the same time as `search/index.html`),
   orders and items per store; the page's inlined order records gave the same order counts.
   Written to `<data>/NOTES.md` only.
2. `status --json` → exit 3 ("run `order-history init`"); `init` → exit 0, folder created
   mode 0700 and recorded in `~/.config/order-history/config.json`; `status --json` → both
   stores `missing`. `NOTES.md` = `LOCAL.md` + the counts table (mode 0600).
3. Amazon: the three export folders gathered into a scratch folder outside the checkout
   (the same three an archived export holds). `import <scratch> --dry-run --json` → exit 0,
   `action: dry_run`, `after` counts equal to step 1, no findings. `import --json` → exit 0,
   `action: imported`, `archived_to: null`, page written ("page shell from local build").
4. Adafruit: `import <checkout>/Adafruit/order_history.csv` dry run then import → exit 0
   both; 0 items (the item lists live in the cache).
5. Copied `items.json` and `lookup_email.txt` to `<data>/adafruit/`, `images.json` to
   `<data>/amazon/`, and `archive/amazon-<date>/` to
   `<data>/amazon/archive/<date>-from-checkout/`.
6. `build` → exit 0; `status --json` → exit 0, both stores `ok`, **orders and items equal to
   step 1 for both stores**; Adafruit `items_unfetched: 0`. Result appended to `NOTES.md`.

No request went to either store (`update` was not run).

  the build date and both stores' counts.

  `data.json` path; narrowed to allow exactly that path (notebook decision).

## Release

Before the tag, rehearsed what could be without a release:

- With `PATH=/usr/bin:/bin` (no node, no npm), an empty scratch `XDG_CACHE_HOME` and a
  scratch copy of the data folder, `build` exited 4 with "no page shell for version 0.1.0:
  download failed (HTTP Error 404: Not Found). It is published at
  `https://github.com/curtisgalloway/order-history/releases/download/v0.1.0/page-shell.html`
  …The existing page is unchanged.", and the page's SHA-256 was unchanged.
- The comparison used below (split each page at its `order-data` element, compare the data
  and the shell separately) reported `data equal: True | shell equal: True` on two copies
  of the same page.

Run by the orchestrator with the user's go-ahead, 2026-10-25, from the main checkout on
`main` after PR #8 merged:

**Tag and release.** Tag `v0.1.0` on `3b5895e`, pushed. The release workflow's conclusion
was success (jobs `shell` and `publish` both success). The release API returned:

```
{"assets":["page-shell.html"],"draft":false,"immutable":true,"tag":"v0.1.0"}
```

**Downloaded-shell check.** The shell cache was cleared; `build` with npm on `PATH` used
"page shell from local build"; `build` again with npm off `PATH` used "page shell from
download" (then cached). Comparing the cached download with the local `web/dist/index.html`,
and the two built pages split at their `order-data` element:

```
shells: byte-identical
pages: data equal: True | shell part equal: True
page_built: 2026-10-25T16:19:18-07:00
```

The release's shell (built in CI on Node 24) is byte-identical to the local build (Node
26), so the page a machine without Node gets is the same page. The comparison files are in
the orchestrator's scratchpad (`release-check/`), not in the repository.
