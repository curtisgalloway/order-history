## Milestone definition

As planned (moved here from the implementation plan at completion):

**Design coverage:** R7

**Dependencies:** M2

**In scope:**

- move `search/app` to `web/`, and read the data from
  `<script id="order-data">`;
- the data `format` number and the page's message when it doesn't match;
- `page.py` with the three-step shell lookup and atomic writes;
- rebuilding after import;
- delete `search/`;
- CI: a `page` job, and a release workflow that attaches `page-shell.html`;
- the required checks become `lint`, `test` and `page`.

**Out of scope:** `update` (M4).

#### Implementation steps

1. Move the folder with `git mv search/app web`. Remove `json.stringify` and
   `generated/`. `main.tsx` parses the script element. The shell is built
   with that element empty.
2. `page.py`:
   - Look in the cache, then try a local build, then download from
     `https://github.com/<owner>/<repo>/releases/download/v<version>/page-shell.html`.
   - Escape `</` in the JSON before putting it in.
   - Write to a temporary file, then rename it into place.
   - Exit 4 when no shell can be found, and leave the existing page alone.
3. `import` calls `page.build()` after a successful swap.
4. Add `.github/workflows/release.yml`. On a pushed `v*` tag it builds the
   shell and uploads it to that release (`contents: write` for that job
   only). Actions are pinned to commit SHAs.
5. Change the required checks without blocking this milestone's own pull
   request. Branch protection requires `build`, which this pull request
   renames to `page`. Before merging, re-run `harden_repo.sh` with
   `lint test page`, with the user's go-ahead. Then confirm with
   `gh api …/protection`.
6. Delete `search/`, and update the `.gitignore` entries. Keep ignoring the
   old in-checkout data paths (R9).

## What was built

- `web/` (moved from `search/app` with `git mv`): `index.html` holds an empty
  `<script id="order-data" type="application/json">`; `src/load.ts` parses it and checks
  `format` against `DATA_FORMAT` (1), returning a message for an empty element, damaged
  JSON or a mismatch; `main.tsx` renders `App` with the data or the message; `App` takes
  the data as a prop. `generated/` and `json: { stringify: true }` are gone.
- `web/test/`: `search.test.ts` runs `tests/search_cases.json` against `search.ts` over the
  fixture data as `page.py` builds it (`tests/fixture_page_data.py`); `load.test.ts`
  covers the data check. `npm --prefix web test` (Node's own test runner and type
  stripping; no new dependency).
- `order_history/page.py`: `find_shell()` (cache → local build → release download, then
  cached), `page_data()`, `to_script_text()` (every `<` written as `<`), `fill()`,
  `build()` (atomic write, mode 0600), `PageError` with exit 4.
- CLI: `import` rebuilds through the `rebuild=` hook (a page failure rolls the import
  back and exits 4); new `build` command; `status` unchanged. `store._swap` keeps a rebuild
  hook's own exit code.
- Vendors gain an optional `SOURCE` (page footer).
- CI: `build` job replaced by `page` (npm ci, build, `test -s`, `npm test`, the page tests
  against the built shell); `lint` no longer lists `search/*.py`; checkouts use
  `persist-credentials: false`.
- `.github/workflows/release.yml`: on a `v*` tag, job `shell` (`contents: read`) checks the
  tag equals `v` + `__version__`, builds and tests the shell and uploads it as an artifact;
  job `publish` (`contents: write`, no checkout, no npm) creates the release if needed and
  attaches `page-shell.html` without `--clobber`. Top-level `permissions: {}`.
- `search/` deleted (`build.py`, both fetchers, the app's old location). `.gitignore`
  ignores `/search/` as a whole (an old checkout's `index.html` and `images.json` there hold
  purchase data), `/web/dist/` and `/web/node_modules/`; the other old data paths stay.
- README, AGENTS.md, GLOSSARY: `search/` instructions replaced by the CLI and `web/`;
  "Page shell" added to the glossary. The full rewrite is M5's.

## Branch protection (plan step 5, gated)

Not run by the milestone. The required checks must be named as GitHub reports the jobs;
the `test` job is a matrix, reported as `test (3.10)` and `test (3.x)` (from `gh run view
40235988038 --json jobs`: `lint`, `test (3.x)`, `test (3.10)`, `build`). A bare `test`
would never report and would block every merge. After this branch's CI is green and with
the user's go-ahead, before merging:

```bash
bash <github-repo-hardening skill>/scripts/harden_repo.sh curtisgalloway/order-history lint page "test (3.10)" "test (3.x)"
gh api repos/curtisgalloway/order-history/branches/main/protection --jq '.required_status_checks.contexts'
```

The second command should print `["lint","page","test (3.10)","test (3.x)"]`.

## Limitations and blockers

- The page was checked in the browser over a loopback HTTP server, not from `file://`,
  because the browser tool refuses file URLs. The page is one file with inline scripts
  (as `search/index.html` was), so `file://` should behave the same; opening it from disk
  once by hand is an open item.
- Until a release exists (M6), the download path 404s and a machine without Node can't
  build the page; the version is `0.1.0.dev0`, so M6 must set `__version__` to the tag's
  version before tagging (`release.yml` refuses a mismatch).
- Adafruit items and Amazon images can't be fetched between M3 and M4: the fetcher scripts
  went with `search/`. M4 ports them from git history (`15fb0ad:search/fetch_*.py`).
- The dev server (`npm --prefix web run dev`) shows the "no order data" message: the data
  is only in built pages now. Rebuild with `order-history build` to see UI changes.
