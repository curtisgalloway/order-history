## Milestone definition

As planned (moved here from the implementation plan at completion):

**Design coverage:** R1 (registration), R3, R4

**Dependencies:** M1

**In scope:**

- `detect` and `install` for both vendors;
- `store.py` for staging, archiving, swapping and rolling back;
- the generic order and item comparison, plus Amazon's renamed and blanked
  digital titles;
- `import` with `--dry-run`, `--force` and `--json`;
- the zip-member safety check;
- the test-only vendor.

**Out of scope:** rebuilding the page after import (a no-op hook until M3).

#### Implementation steps

1. `detect`:
   - Amazon: a zip or folder containing `Your Amazon Orders/Order History.csv`.
   - Adafruit: a CSV whose header matches the export's columns.

   Detection reads contents only.
2. `install` copies a folder, or extracts a zip into an empty staging folder.
   Before extracting, every member is checked: an absolute path, a `..`
   component or a symlink makes the import exit 30.
3. `store.import_export()` runs the design's import flow, steps 1–7.
   Rollback restores `current/` if a step from 5 on fails. A leftover
   `.staging-*` folder is cleaned up at the start of the next import and
   reported by `status`.
4. `compare(old, new)` gives orders and items added and removed, plus each
   vendor's own findings. Text output is a short summary; `--json` gives the
   full lists.
5. Register a test vendor inside a test to show R1: no core edits.

#### Acceptance criteria

- [ ] Importing an Amazon fixture zip into an empty data folder installs it as
  `current/` and reports every order as added.
- [ ] Importing a newer fixture archives the old one to `archive/<as_of>/` and
  reports the exact differences, including a renamed digital title.
- [ ] `--dry-run` reports and leaves the folder byte-for-byte unchanged.
- [ ] An older export exits 30 without `--force`, and imports with it.
- [ ] A file no vendor claims, or that two claim, exits 2 and changes nothing.
- [ ] A zip with a `../x` member exits 30, and nothing is written outside staging.
- [ ] A failure injected after the archive step leaves the previous
  `current/` in place.
- [ ] Both vendors work from a zip, a CSV and a directory, wherever the vendor
  supports that format.

#### Testing and review

- **Tests:** each criterion above, built from fixture zips made in `setUp`.
- **Review focus:** filesystem safety (the rename order, rollback, extracting
  zips), and that an import never deletes anything.

#### Session sizing

Start from the design's "Import flow" section and M1's vendor modules. The
risk is in edge cases of the swap and rollback. Split point if it grows: land
detect and install with `--dry-run` first, then the swap.

## What was built

- `order_history/store.py`: the import flow (claim, stage, compare, archive, swap,
  rebuild hook, rollback), the zip and folder safety checks, the import lock, and the
  failed-rollback note (`<vendor>/IMPORT-FAILED.txt`).
- Vendors gain `install(src, dest)`, `read(folder)` (an export alone, no caches) and, for
  Amazon, `compare(old, new)` (renamed and blanked titles). `load()` is now `read(current)`
  plus the caches.
- CLI: `import PATH [--dry-run] [--force] [--json]`; `status` reports leftover staging
  folders, a failed-rollback note, and `import_running`.
- Exit codes beyond the design's table, per the house CLI bands: 20 (another import is
  running, or a failure was rolled back), 21 (a rollback failed, or a failed-rollback note
  is present).
- `tests/test_import.py` (39 tests): invented Amazon and Adafruit exports written into temp
  folders in `setUp`; every filesystem operation happens inside the test's temp folder.

### Acceptance criteria

- [x] A newer export archives the old one to `archive/<as_of>/` and reports the exact

- [x] `--dry-run` reports and leaves the folder byte-for-byte unchanged (paths, modes and
  bytes snapshotted): `DryRunTest` (empty folder, with a current export, with a leftover

- [x] An older export exits 30 without `--force` (data unchanged) and imports with it:
  `OlderExportTest.test_refused_then_forced`.
- [x] Unclaimed (text file, plain folder, missing path) or doubly claimed files exit 2 and
  change nothing: `DetectionTest.test_unrecognized`, `test_ambiguous`.
- [x] A `../x` member exits 30, and nothing is written outside staging (or anywhere: the
  data folder and the downloads are unchanged and no `evil-x` file exists under the test's

- [x] A failure injected after the archive step leaves the previous `current/` in place:

- [x] Both vendors work from the formats they support: Amazon from a zip and a folder

## Limitations and blockers

- Rebuilding after import is a no-op hook until M3, as planned.
- Adafruit item counts in a report are always 0: its export has no item lines (they come
  from `items.json`, filled in M4).
- Importing a folder copies the whole folder. The in-checkout Amazon export sits at the
  checkout root beside the code, so M6's migration must gather it into its own folder (or
  import the original zip) first. In the backlog.
- The import lock uses `fcntl`; without it (Windows, not a goal) imports are unlocked.
