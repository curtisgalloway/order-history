## Milestone definition

As planned (moved here from the implementation plan at completion):

**Design coverage:** R8, R9

**In scope:**

- `SKILL.md`, `vendors/amazon.md` and `vendors/adafruit.md`;

#### Implementation steps

1. Write `SKILL.md`, covering:
   - when to use the skill;
   - first run (`init`);
   - the import flow, including reporting the comparison to the user;
   - search, status and update;
   - the privacy note (search results go to the model provider);
   - migrating from an in-checkout layout.

   It points to `vendors/<id>.md` for each store's quirks and how to get its
   export. The export-format sections of AGENTS.md move into those files.
2. `--skill` prints `SKILL.md` through `importlib.resources`, with the version
   stamped in.
3. Write the plugin manifest. Check how plugins are discovered and validated
   in Claude Code's current documentation before writing it, rather than
   guessing.
4. Add `pyproject.toml` (`[tool.uv] package = true`, a script entry point,
   explicit packages).
5. Update the docs:
   - README: install as a plugin, with `uv tool`, or from the script path.
   - AGENTS.md: the developer guide for this repo, plus a pointer to the
     skill.
   - GLOSSARY: add vendor module, data folder, page shell, skill and plugin.

#### Acceptance criteria

- [ ] `order-history --skill` prints exactly what `SKILL.md` contains, plus
  the version line. A test checks this.
- [ ] The plugin manifest passes the validator found in step 3, or a manual
  review against the documented schema if there is no validator.
- [ ] `uv tool install .` puts a working `order-history` on `PATH`.
- [ ] The docs mention no `search/` commands. The privacy note appears in both
  the README and SKILL.md.

#### Testing and review

- **Tests:** the `--skill` equality test. Install in a temporary environment
  and run `order-history status`.
- **Review focus:** the skill is understandable on a cold start by an agent
  that has never seen this repo; it works under any agent (use the
  `agent-agnostic-skills` portability scan).

#### Session sizing

This is mostly writing; it's small to medium. Split point if it grows: land
the skill and vendor docs first, then packaging and the plugin.

  `order_history/vendors/<id>.md -> ../../../vendors/<id>.md`, which the wheel stores as

  locale. Exit 2 for an unknown store, 3 for a store without an instruction file.

  `.claude-plugin/marketplace.json` (this repo as its own one-plugin marketplace,

- `pyproject.toml`: setuptools, `package-dir` onto `skills/order-history/scripts`, explicit
  packages, the `.md` package data, the version read from `order_history.__version__`,
  `[tool.uv] package = true`, the `order-history` script.
- README (install three ways, privacy section, command table), AGENTS.md (now the developer
  guide; export formats moved out), GLOSSARY (archive, data folder, frontmatter,
  marketplace, model provider, plugin, skill, staging folder, uv tool, vendor module),
  design exit-code table (4, and 20/21 per command), `.gitignore` (`build/`, `dist/`,
  `*.egg-info/`).
- `store.py` and `tests/test_import.py`: formatting only (pyink now reads
  `requires-python` and uses parenthesized `with`).

## Limitations and blockers

- The plugin was validated but not loaded into a Claude Code session (`/plugin`,
  `--plugin-dir`): that means launching Claude Code, which this milestone doesn't do. M6's
  cold-start check is the natural place, or the user by hand.
- Until a release exists, a plugin or `uv tool` install with no Node can't build the page
  (exit 4, import undone). M6 tags `v0.1.0`; `__version__` and `plugin.json`'s version
  must both become `0.1.0` first.
- From the plugin cache (a copy of this repository, `web/` included), `page.py` takes the
  development path whenever `npm` is on `PATH`: it runs `npm ci` and `npm run build`
  inside the plugin's cached copy instead of downloading the shell (backlog).
- `--skill` from a clone needs symbolic-link support in the checkout (not Windows by
  default; Windows is not a goal, design A1). Installed copies hold plain files.
- The Claude Code install line (`/plugin install order-history --marketplace
  curtisgalloway/order-history`) comes from the validator's advice and the docs; it can
  only work once this branch is on `main` and was not run.
